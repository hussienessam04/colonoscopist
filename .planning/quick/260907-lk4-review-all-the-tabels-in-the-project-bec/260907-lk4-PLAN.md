<objective>
Fix the broken pagination logic across the three tables that render paginated data (PatientProcedures, PatientsList, Audit). The user reports the pagination is "mostly not working right"; root cause analysis found three distinct bugs:

1. **PatientProcedures silently caps at 200 procedures with NO pagination UI** — the worst bug. If a patient has >200 procedures, the rest are silently dropped, never reachable. The page fetches `pageSize: 200` once, renders all rows, no Next/Previous button, no "page X of Y" indicator, no way to navigate.

2. **PatientsList + Audit — user gets stuck on an empty page after delete / total shrinks below current page**. The `total` field refreshes via `refetch()`, but the `page` state is only reset to 1 when a filter changes. After deleting the last patient on page 5, `total` drops to 99, `totalPages` drops to 3, but `page` is still 5 → the Next button is disabled (correct), but the Previous button is enabled (also correct), the user sees an empty table, and "Showing 101-99 of 99" nonsense in the range line. There is no auto-clamp logic.

3. **All three tables — `totalPages = Math.max(1, Math.ceil(total / pageSize))` mis-reports "Page 1 of 1" when total=0**. Should clamp to 0 pages (or special-case the empty range UI).

Output: every paginated table reads as a real list — user can navigate, never gets stuck on an empty page, never sees nonsensical range strings, and never silently drops data.
</objective>
