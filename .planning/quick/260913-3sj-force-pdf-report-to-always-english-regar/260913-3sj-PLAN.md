# Force PDF report to always be English + i18n sweep of remaining hardcoded labels

## Task 1 — Force PDF to always render in English

**Files:**
- `src/main/ipc/reports.ts` (REPORTS_REGEN_PDF handler — hardcode `language: 'en'` + drop dead imports + `reportsRepo.getById(id)` lookup)
- `tests/integration/ar-pdf-magic.test.ts` (rewrite assertion now that PDFs are always EN; keep the magic-bytes + >5KB smoke shape)

**Action:**

1. **`src/main/ipc/reports.ts` REPORTS_REGEN_PDF handler** (around lines 347-374): replace the per-doctor language lookup with a hardcoded `language: 'en'`. PDF clinical documents stay in English per the doctor's explicit preference (Arabic locale labels in the template remain available via the `language` flag, but the renderer's UI language no longer drives PDF output). The new handler body becomes:

   ```ts
   // PDF reports always render in English regardless of UI language preference.
   // The renderer's i18n language is decoupled from the clinical document.
   const language: 'en' | 'ar' = 'en';
   const result = await renderReportPdf(id, { language });
   ```

   Drop the now-unused `const reportRow = reportsRepo.getById(id);` lookup, the `if (reportRow) { ... }` block, and the `language` metadata in the `audit()` call (or keep `language` in the metadata as a fixed `'en'` literal for log traceability — pick literal `'en'`).

2. **Drop the dead imports** at the top of `reports.ts`: `import { doctorProfileRepo } from '../db/doctor-profile-repo';` (line 51) and `import { userRepo } from '../db/users';` (line 52). `grep` confirms these two imports are now unreferenced anywhere in the file (they were only used inside the deleted REPORTS_REGEN_PDF block). Keep all other imports untouched.

3. **Update the AR PDF integration test** `tests/integration/ar-pdf-magic.test.ts`:
   - Rename the top header comment block from "AR PDF ship-gate (RPT-06 / D-27)" framing to "PDF ship-gate (RPT-06) — always-English post-toggle" framing (the title is now an internal smoke, not a language-feature check).
   - Drop the `THRESHOLD DEVIATION` block — the deviation existed only because language='ar' forced English glyph rendering with unused NotoSansArabic. Now language is always 'en', the threshold is the original D-27 >50KB baseline… BUT @react-pdf/renderer 4.5.1 still only embeds glyph subsets, so an EN-only report with one screenshot lands at ~10KB. Bump the threshold to `> 5_000` (matching the existing deviation) and add a 1-line `// ponytail:` comment explaining "EN-only PDF with one 6KB JPEG + Helvetica = ~10KB; 5KB catches the three crash modes (0KB crash / font-register-fail empty PDF / wrong format)."
   - Drop the `doctorProfileRepo.upsert({ ... language: 'ar' })` block — it's a no-op now.
   - Drop the `language: 'ar'` argument from `renderReportPdf(...)` — orchestrator defaults to 'en', or pass `{ language: 'en' }` explicitly to make the test contract read "EN-only PDF, document the why".
   - Update the `it('renders an AR-language PDF ...')` description to `'renders an EN-only PDF via the full orchestrator path'`.

4. **`src/main/pdf/render-report-pdf.ts:185-194`** — the orchestrator's language fallback chain is still valid as a safety net (when `opts.language` is undefined, it falls back to profile → user → 'en'). With the IPC handler now always passing `language: 'en'`, the orchestrator's fallback only fires if some other caller invokes `renderReportPdf` directly without a language. Leave the fallback chain untouched — it's still correct (the final 'en' default is now load-bearing for any future test/internal caller).

**Verify:**
- `npm run typecheck` (or `tsc --noEmit`) passes.
- `grep -n "doctorProfileRepo\|userRepo" src/main/ipc/reports.ts` returns ZERO matches (imports dropped, no other usage).
- `RUN_SMOKE=1 npm run test:integration:smoke:phase7` passes — the rewritten EN-only PDF smoke writes a valid file with '%PDF' magic bytes and >5KB size.
- Manual: set UI to Arabic, finalize a report, regenerate PDF, open the file → every visible string is English (header, anatomy labels, footer).

**Done:**
- `REPORTS_REGEN_PDF` always passes `language: 'en'` regardless of `doctorProfile.language` or `users.language`.
- `doctorProfileRepo` + `userRepo` imports removed from `reports.ts`.
- AR PDF smoke test still green after the rewrite.
- PDF output is identical regardless of UI language (EN UI → EN PDF; AR UI → EN PDF).
