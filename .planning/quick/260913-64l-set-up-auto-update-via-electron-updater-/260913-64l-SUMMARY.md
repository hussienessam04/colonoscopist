# Quick task 260913-64l — Auto-update via electron-updater + GitHub Releases

3 atomic tasks, ~16 min, 1 main-process module + 1 renderer hook + 1 page update + 1 ops doc. End-to-end shipping: a clinic on v0.1.0 will see an "Update available" card in Settings → About on the next launch (or every 6 hours while running), opt-in to the download, and click "Restart now" to apply it.

## Task 1 — Install + electron-builder publish config + docs

- `npm install --save electron-updater` — adds `electron-updater ^6.8.9` to **dependencies** (not devDeps; electron-builder does NOT bundle from devDeps, and main-process `import` resolves to undefined at runtime if missing from the production tree).
- `package.json` build.publish block: `{ provider: 'github', owner: 'hussienessam', repo: 'colonoscopist', releaseType: 'release', publishAutoUpdate: true }`. NO `token` field — GH_TOKEN comes from the maintainer's shell / GitHub Actions secret at publish time.
- `publish:gh` (--publish always) + `publish:dry` (--publish never) scripts added.
- `docs/publishing.md` — 1-page ops guide covering: bumping version, cutting a release, GitHub Actions secret, doctor sees the update (boot + 6h re-check), publish:dry smoke check.

## Task 2 — Main-process auto-updater wiring

- `src/main/auto-update.ts` (NEW, ~110 lines) — `initAutoUpdater()`:
  - 4 event listeners: `update-available`, `download-progress`, `update-downloaded`, `error`
  - `autoDownload = false` (clinic Wi-Fi is metered; explicit opt-in via the Download button)
  - `autoInstallOnAppQuit = false`
  - Initial `checkForUpdates()` + 6h `setInterval` re-check
  - Dev runs short-circuit silently (`!app.isPackaged`)
  - Module-scoped `AppUpdateState` object — mutated by events, read by renderer via IPC clone
  - 4 IPC handlers: CHECK (fire-and-forget), GET_STATE (clone), DOWNLOAD (await + refresh), INSTALL (quitAndInstall)
  - All events + errors route through `logEvent()` (existing crash logger) so the diagnostic bundle includes update traces.
- `src/main/index.ts` — calls `initAutoUpdater()` after `app-ready` so the first APP_UPDATE_GET_STATE poll returns a populated state.
- `src/shared/ipc-contract.ts` — 4 new IPC constants + `AppUpdateState` type + `app.update` namespace.
- `src/preload/index.ts` — bridges the 4 channels under `window.api.app.update.*`.
- `src/main/license/gate.ts` — 4 new EXEMPT channels (auto-update is workstation-level; expired license should still get the notification).
- `tests/main/license/gate.test.ts` — `EXEMPT_CHANNELS.size` bumped 20 → 24 + 4 new entries in the `expected` array.

## Task 3 — Renderer UI

- `src/renderer/src/hooks/useUpdater.ts` (NEW, ~80 lines) — SWR-style hook mirroring `useLicenseStatus()` exactly. Polls APP_UPDATE_GET_STATE every 30s; exposes `check()` / `download()` / `install()` callbacks. Optional-chain guards on `window.api` for tests + HMR edge cases.
- `src/renderer/src/pages/SettingsAbout.tsx` — conditional update card above the existing app-info card (gated on `available || downloaded || error`). Surfaces progress, Download/Restart CTAs, Check-now button. `state.error` → global toast via `sonner`. Up-to-date footer line in the app-info card when no update is queued.
- `src/renderer/src/components/SettingsLayout.tsx` — optional `updateBanner` prop renders between header and content card (future pages can opt in).
- `src/renderer/src/i18n/{en,ar}/translation.json` — new `update` namespace (11 keys each; AR hand-written per D-20). D-24 parity test still passes.
- `tests/renderer/setup.ts` — `app.update.*` mocks added to `MockApi`; default `getState` returns an all-false shape so the page renders without per-test seeding.
- `tests/renderer/pages/settings-about.test.tsx` (NEW, 5 tests) — default render + update-available state + Download IPC click + progress label + downloaded/Restart state.
