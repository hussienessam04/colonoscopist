# Quick task 260913-5b0 — Production hardening: electron-builder + crash logger + Diagnostics page

## Summary

Three atomic commits ship the production-hardening baseline:

1. **electron-builder config + install + build scripts** (`c028d3f`) — Windows NSIS installer + portable single-folder build targets; `npm run package` and `npm run package:portable` scripts wired to `electron-vite build && electron-builder --win <target>`.
2. **Structured crash logger + `APP_GET_DIAGNOSTIC` IPC** (`ae30d29`) — `process.on('uncaughtException')` + `'unhandledRejection')` capture writes `[iso] [level] event | key=value | ...` lines to the existing `startup.log`; new `app:get-diagnostic` channel returns the workstation bundle (versions + paths + last 200 log lines + license state + storage config). EXEMPT from the license gate.
3. **Settings → Diagnostics page** (`ff12f52`) — sidebar entry between About and Storage; page mirrors `SettingsAbout` byte-for-byte; Copy button writes the JSON dump to the clipboard via the existing `clipboard.copyText` IPC. EN+AR i18n parity (`diagnostics` namespace).

Out of scope per user: code signing, auto-update, .ico file, Linux/Mac targets.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Replaced `require('node:path').sep` in `diagnostics.ts` with a `path` import**

- **Found during:** Task 2 typecheck
- **Issue:** The plan template's `diagnostics.ts` used `require('node:path').sep` inline inside the handler, which would pull `require` into the TS-compiled output and trip the `eslint-disable-next-line @typescript-eslint/no-require-imports` rule that the existing `startup-log.ts` was forced to use. Better fit: an ESM `import path from 'node:path'` at the top of the file (consistent with the rest of the codebase, e.g. `paths.ts`, `data-location-config.ts`).
- **Fix:** Imported `path` at the top of the file and used `path.join()` for the userData/logs/currentLogPath resolution.
- **Files modified:** `src/main/ipc/diagnostics.ts`
- **Commit:** `ae30d29`

**2. [Rule 1 - Bug] Added `getDataLocationConfig()` failure-path log line in `diagnostics.ts`**

- **Found during:** Task 2 review (consistency with the license-status failure path)
- **Issue:** The plan template wrapped `getLicenseStatus()` in try/catch with no log; the new code wraps `getDataLocationConfig()` in try/catch with no log. Inconsistent — a broken license cache writes a `diagnostics.license_status_failed` warn line, but a broken storage config silently degrades. A doctor hitting both failure modes would see one logged + one silent.
- **Fix:** Symmetric failure-path logging on both branches (license status emits `diagnostics.license_status_failed`; storage emits `diagnostics.storage_location_failed` if it ever throws). Keeps the page render path bullet-proof — a single broken subsystem doesn't block the rest of the bundle.
- **Files modified:** `src/main/ipc/diagnostics.ts`
- **Commit:** `ae30d29`

No plan deviations — only inline upgrades that the lazy "smallest correct fix" rule calls for. The plan was followed otherwise.

## Files of Note

### `src/main/ipc/diagnostics.ts` (new, 96 lines)

EXEMPT-from-gate IPC pattern mirrored from `src/main/ipc/storage.ts`. Each field is computed best-effort with try/catch so a broken license cache or missing config never blocks the diagnostic read. Uses the existing `logStartup` writer (now extended with `logEvent` + `readRecentLogLines`).

### `src/main/startup-log.ts` (modified, +42 lines)

Two new exports:
- `logEvent(level, event, context?)` — `[iso] [level] event | key=value | ...` lines. Error objects are stringified as `message + stack` with newlines escaped to keep each entry a single line.
- `readRecentLogLines(max = 200)` — tail-N lines for the Diagnostics page. Returns `[]` on file missing (boot path hasn't fired yet).

The existing `logStartup()` writer is untouched — boot logs continue to write `better-sqlite3=<version>` as before.

### `src/main/index.ts` (modified, +28 lines)

Crash handlers at module top (BEFORE `app.whenReady`) so failures during the boot path itself land in `startup.log`. `registerDiagnosticsIpc()` registered FIRST inside the `whenReady` callback.

### `src/renderer/src/pages/SettingsDiagnostics.tsx` (new, 143 lines)

Verbatim mirror of `SettingsAbout.tsx`:
- same Card chrome (border-`#E0D9C6`, bg-`#FBF7EE`, dual-shadow)
- same `grid-cols-3 gap-2 pb-2 border-b border-border` row treatment
- same teal small-caps `CardTitle`
- same `font-mono break-all` value typography
- same `SettingsLayout` wrapper (`title`, `subtitle`, `activeTab="diagnostics"`, `backTestId="settings-diagnostics-back"`)

State: `useEffect` fires `window.api.app.getDiagnostic()` on mount; cancellable promise pattern with `cancelled` flag prevents state updates after unmount. Copy handler calls `window.api.clipboard.copyText({text: JSON.stringify(diagnostic, null, 2)})` and toasts success/error.

### `src/renderer/src/i18n/{en,ar}/translation.json`

New `diagnostics` namespace (19 keys per locale). AR strings hand-written per D-20 — D-24 parity test passes.

### `tests/renderer/setup.ts`

`MockApi` gains `app.getDiagnostic` with a valid default `DiagnosticInfo` so any renderer test that mounts the page without per-test seeding renders cleanly.

### `tests/main/license/gate.test.ts`

`EXEMPT_CHANNELS.size` assertion bumped from 19 to 20; `'app:get-diagnostic'` added to the expected channel names array.
