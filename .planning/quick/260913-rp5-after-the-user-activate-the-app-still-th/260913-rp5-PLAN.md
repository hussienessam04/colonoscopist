# Quick Plan: 260913-rp5

**Task:** After license activation, the capture workflow pages still render the gated-empty-state ("License required — open Settings → License to activate."), preventing the doctor from picking a device or starting a recording. The renderer hooks detect the IPC gate's `{ok:false}` rejection on mount, set `gated=true`, but never re-fetch when license state transitions to `licensed`.

**Date:** 2026-09-13

## Root cause

`useCaptureDeviceMap`, `useProcedures`, and the inline `useEffect`s in `ProcedureRoom` / `ProcedurePreview` / `SettingsCapture` all have `gated` state set to `true` when a gated IPC returns `{ok:false, code:'IPC_LICENSE_*'}`. The state is set on mount but never cleared:

- `useCaptureDeviceMap.ts:34` — sets `error` when `listDevices` is gate-rejected
- `useProcedures.ts:91` — sets `gated=true` when any of 4 procedure/notes/screenshots calls is gate-rejected
- `ProcedureRoom.tsx:89-98` — `getDefaultDevice` useEffect with `[]` deps, sets `savedDevice=null` when gate-rejected (no `gated` flag, but same root cause)
- `ProcedureRoom.tsx:122-128` — `getPreset` useEffect, same pattern
- `ProcedurePreview.tsx:148-156` — `procedures.create` call sets `gated=true` on null
- `SettingsCapture.tsx:88-99` — hydration useEffect, sets `gated=true` on gate rejection
- `ProcedureReview.tsx:225-265` — patient fetch useEffect, sets `patientGated=true` on gate rejection

After activation, the IPC gate passes on subsequent calls — but no re-fetch happens. The user is stuck on the gated-empty-state.

The fix is the missing wire: each affected hook/effect needs to subscribe to `LICENSE_CHANGED_EVENT` and re-fetch when the event fires. The event is already dispatched by `License.tsx` after a successful `pickAndActivate` (commit `9ad4e6c`).

## Fix

Add a single helper hook `useLicenseChangeRefresh(refresh)` that subscribes to `LICENSE_CHANGED_EVENT` and calls the callback when it fires. Apply it to every gated hook + every gated inline `useEffect` in the capture flow:

1. **NEW:** `src/renderer/src/hooks/useLicenseStatus.ts` — add `useLicenseChangeRefresh` export
2. **MODIFIED:** `src/renderer/src/hooks/useCaptureDeviceMap.ts` — wire `useLicenseChangeRefresh` to re-fetch on event
3. **MODIFIED:** `src/renderer/src/hooks/useProcedures.ts` — wire `useLicenseChangeRefresh` to `refresh`
4. **MODIFIED:** `src/renderer/src/pages/ProcedureRoom.tsx` — wrap the two useEffects (getDefaultDevice, getPreset) with a license-change listener that clears stale state and re-fetches
5. **MODIFIED:** `src/renderer/src/pages/ProcedurePreview.tsx` — clear local `gated` state on license change
6. **MODIFIED:** `src/renderer/src/pages/SettingsCapture.tsx` — clear local `gated` state on license change
7. **MODIFIED:** `src/renderer/src/pages/ProcedureReview.tsx` — wrap the patient fetch useEffect with a license-change listener

The `LICENSE_CHANGED_EVENT` is dispatched only by `License.tsx` on successful activation, so the listener is safe to fire on every event.

- No changes to i18n keys (the gated-empty-state text stays — it correctly describes the unlicensed state when it actually applies).
- Tests for the new helper + a regression test that proves activation clears `gated` across the capture flow.
