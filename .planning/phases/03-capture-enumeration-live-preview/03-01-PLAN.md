<open_questions>
These three items were open at the close of `/gsd-discuss-phase`. They are formalized as locked decisions for Phase 3 implementation. Each is referenced in the relevant task action.

## Q-A: Auto-detect heuristic matched-regex in audit metadata

**DECISION:** When `getPreset` first-read invokes `autoDetectPreset` and materializes the saved preset row, the audit row's `metadata` carries `{ deviceName: canonical, preset: 'sd'|'hd', matched: 'sd-pattern-EasyCap' | 'hd-pattern-HDMI' | ... }`. The `matched` field names the FIRST regex group that triggered. Every subsequent read AND every manual save logs `{ deviceName, preset }` only (no `matched` field). Absence of `matched` in audit metadata therefore indicates either a repeated read or a manual save.

## Q-B: Finish button route target

**DECISION:** `useRoute()` (Plan 03-02) tracks `previousRoute` as part of its state slice. The Finish button navigates to `previousRoute ?? { name: 'patients' }`. Until Procedure Room is opened from Patient Detail in Phase 4, the previousRoute fallback to `{ name: 'patients' }` keeps the doctor one click away from a known-safe surface.

## Q-C: Settings preview state persistence

**DECISION:** Settings → Capture preview state (`isPreviewing`, current `MediaStream`, error text) is component-local React state inside `SettingsCapture.tsx`. Only an explicit Save button calls `capture.setDefaultDevice({ deviceId })` and `capture.setPreset({ deviceId, preset })`. Changing the device dropdown or preset radio re-opens the preview stream (D-09 reactivity) without persistence; closing or navigating away tears the preview down and writes nothing.
</open_questions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|---|---|
| Renderer → capture IPC | Untrusted renderer payloads cross the contextBridge. doctorId is NEVER accepted from the renderer (BLOCKER 4). |
| ffmpeg stderr → main parser | External process output is parsed before becoming device identity. |
| Main → SQLite settings/audit | Main-only persistence stores doctor and device configuration. |
| Renderer → empty-state audit sink | Renderer fires `noDeviceAudit` when the empty state renders; main treats the event as a marker, not a state-changer. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-3-01 | Tampering | `devices.ts` / ffmpeg stderr | high | mitigate | Parse only quoted VIDEO-section names, canonicalize once, reject empty names; test Unicode/whitespace round-trip. |
| T-3-02 | Elevation of Privilege | `ipc/capture.ts` | high | mitigate | Derive `doctorId` from `requireSession()` exclusively; validate every device/preset input with zod in main; the `setPreset`/`setDefaultDevice` payloads do not include a doctorId field. |
| T-3-03 | Denial of Service | ffmpeg enumeration child process | medium | mitigate | One bounded enumeration call per launch/page entry, collect stderr, handle `error`, resolve on close without recording handlers. |
| T-3-04 | Repudiation | capture audit writes | medium | mitigate | Record canonical device and preset metadata for every persistent capture mutation; `capture.no_device` event for empty-state renders. |
| T-3-05 | Tampering | Electron webPreferences | high | mitigate | Keep `permissions: ['media']`; security baseline test asserts all five flags (`contextIsolation`, `nodeIntegration`, `sandbox`, `webSecurity`, `permissions`) remain set (BLOCKER 3). |
| T-3-06 | Tampering | npm packages | high | mitigate | Package legitimacy audit in 03-RESEARCH.md approves only `ffmpeg-static` and `@types/ffmpeg-static`; slopcheck + blocking human verification on any classification change. |
</threat_model>
