<objective>
Close G-03-8 by making the ProcedureRoom `Stop releases every track` and `Finish stops the active stream` tests deterministic under `npm run test:unit` (Electron-as-Node ABI). The race is in the test's wait pattern: the test waits for the Stop Preview button to render (which happens when `starting === true`), but the `.then` from `getUserMedia` hasn't resolved yet. When the test clicks Stop/Finish, `streamRef.current` is null, and `release()` doesn't stop the tracks. The `.then` resolves later, and the cancellation branch stops the tracks. But the test's `waitFor` might not see the tracks stopped within the timeout under the Electron-as-Node runtime.

Purpose: CAPT-03's cleanup invariants become verified by automated tests (Stop and Finish release every track). The hook's release ordering is pinned by the integration contract so a future refactor cannot re-introduce the race.

Output: The Stop and Finish tests await the `getUserMedia` mock's resolved promise before clicking Stop/Finish, ensuring the `.then` has fired and `streamRef.current` is populated. The hook's `release()` ordering is documented with a ponytail comment block. The integration contract statically asserts the ordering with three regex assertions on `USE_VIDEO_PREVIEW_SRC`.

This plan is renderer + tests only; no IPC, no main-process change, no schema change.

From `src/renderer/src/hooks/useVideoPreview.ts:88-140` (useEffect — the in-flight `.then` chain):
```ts
useEffect(() => {
  if (!startRequested || !browserDeviceId) return;

  release();
  const request = requestRef.current;
  setStarting(true);
  setActive(false);
  setError(null);

  const video: MediaTrackConstraints = { ... };

  void navigator.mediaDevices
    .getUserMedia({ video, audio: false })
    .then((stream) => {
      if (request !== requestRef.current) {
        // CANCEL: a newer release() ran while we were waiting; stop the
        // tracks so the OS handle is not leaked.
        stream.getTracks().forEach((track) => track.stop());
        return;
      }
      streamRef.current = stream;
      if (videoRef.current) {
        try {
          videoRef.current.srcObject = stream;
        } catch {
          // some test environments (e.g. happy-dom) reject non-MediaStream
          // objects on srcObject assignment; ignore so the preview can
          // still be tracked in state.
        }
      }
      setStarting(false);
      setActive(true);
    })
    .catch((cause: unknown) => {
      if (request !== requestRef.current) return;
      setStarting(false);
      setActive(false);
      setStartRequested(false);
      setError(previewError(cause));
    });

  return release;
}, [browserDeviceId, framerate, release, startRequested, resolution?.[0], resolution?.[1]]);
```
The cancellation branch (`request !== requestRef.current`) stops the tracks. The race: when the test clicks Stop/Finish before the `.then` resolves, `release()` runs in `preview.stop()` (requestRef.current ++), then the unmount cleanup runs `release()` again (requestRef.current ++), then the `.then` resolves and sees `request !== requestRef.current` and stops the tracks. The test's `waitFor` polls every 50ms; under Electron-as-Node ABI the microtask may not have resolved before the first poll, so the test sees zero track stops and fails.
