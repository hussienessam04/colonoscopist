# Phase 2 Plan 04 — Gap Closure: Fix migration loader ENOENT on cold start

<objective>
Resolve UAT gap G-2-1: the app crashes on cold start with
`ENOENT: no such file or directory, scandir '...out\main\migrations'`
because `src/main/db/migrations.ts` tries to read migrations from
the filesystem at a path that doesn't exist after `electron-vite`
bundles the source into `out/main/index.js`.

The fix: switch the loader to embed the SQL string in the bundle
via Vite's `?raw` query suffix, so the SQL ships inside the JS
output and no filesystem read is needed at runtime. This works
identically in dev (`npm run dev`), unit tests (vitest), and
packaged ASAR builds.
</objective>
