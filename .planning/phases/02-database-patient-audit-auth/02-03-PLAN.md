# Phase 2 Plan 03 — Renderer (Wizard + Login + Patient List + Settings → Users)

## Objective

Ship the renderer surface for Phase 2: a state-based router that drives the wizard on first launch → two-step login on subsequent launches → patient list with search + soft-delete toggle → patient create/edit form → Settings → Users (admin only). Install the small slug of shadcn primitives needed (Card, Dialog, DropdownMenu, Select, Checkbox, Avatar, Tooltip, Sonner). Tests cover every page.

**User story (MVP mode):** *As a doctor at the workstation, I want to open the app and either set it up (first time) or sign in and immediately find the patient I need to scope the next procedure to, so that the recording flow never has to wait on me.*

## Threat Model

| Threat | STRIDE | ASVS | Mitigation |
|--------|--------|------|------------|
| XSS in user-typed patient name / notes | Tampering | V10 | React's default text rendering escapes; no `dangerouslySetInnerHTML` anywhere; shadcn primitives are sanitized; CSP deferred to Phase 7 |
| Renderer dispatches raw SQL | Elevation of Privilege | V1 | `nodeIntegration: false`, `contextIsolation: true`, `sandbox: true` (Phase 1 baseline); all DB access stays in main via IPC |
| Replay of `auth:bootstrap` after first run | Spoofing | V2 | `wizardBootstrap` throws `IPC_VALIDATION` if `users` already has a row; the IPC handler does not call `auth:bootstrap` from the wizard on subsequent launches (`auth:status` check on mount) |
| `setWindowOpenHandler` policy bypass | Tampering | V10 | The mailto link is opened via `window.location.href = mailto:...`, which does not trigger `setWindowOpenHandler`; the existing handler in `window.ts` blocks any non-`file:` URL from `window.open` |
| State-based router exposed to URL injection | Tampering | V1 | No URL-based routing in v1; the route is in renderer state only; deep-link URLs are the v2 upgrade path (no `react-router` dep) |
| Idle PIN entry reads | Information Disclosure | V2 | 10s idle timer clears the PIN; back arrow always clears it; the field is `type="password"` not `type="text"` |
| Admin self-removal via Settings users | Denial of Service | V4 | "Remove" is disabled on the admin's own row (button + tooltip) |
| Form submission while a previous submit is in flight | Tampering | V11 | Forms disable the submit button while `react-hook-form` is in `isSubmitting` state; IPC errors render inline |

## Must-Haves

### Truths
- On first launch, the wizard collects full name + clinic name + PIN + confirm PIN and creates the admin user atomically.
- On subsequent launches, the two-step login shows the user list (avatar + name + last-login) → tap row → PIN entry; back arrow returns to the list.
- A wrong PIN shows the inline red error "Incorrect PIN" and clears the field; the Enter button briefly disables.
- A logged-in user lands on the Patient List; search by name substring or MRN exact filters the rows; "+ New patient" opens the form.
- The Patient List "Show deleted" toggle reveals soft-deleted rows with a "Deleted" badge; restore is admin-only.
- Settings → Users is reachable only by the admin; add / remove / reset PIN for non-admin users; admin cannot remove themselves.
- "Forgot admin PIN?" affordance on the login screen opens the Phase 8 mailto handoff with the machine fingerprint.

### Prohibitions
- **No `react-router`** — state-based router only.
- **No nodeIntegration in the renderer** — Phase 1 baseline is unchanged.
- **No optimistic mutations** — every IPC round-trip is awaited; sonner toast on success / error.
- **No clinical field values in `audit_log.metadata`** — same rule as Plan 02-01; the renderer never bypasses the IPC contract.
- **No "Remove" on the admin's own row** — disabled with a tooltip.
- **No automatic sign-out on lockout** — the locked user's row stays in the user list; tapping it shows the lockout message (D-08: back arrow still works).

### Key Links
- `src/renderer/src/App.tsx` → `window.api.auth.status()` → `src/main/auth/session.ts` — the renderer's route decision is driven by the main-process session state.
- `src/renderer/src/pages/Login.tsx` → `window.api.auth.login` → `src/main/auth/index.ts` (login) — the renderer's PIN entry funnels into the rate-limit + audit-enforcing service.
- `src/renderer/src/pages/PatientsList.tsx` → `window.api.patients.list` → `src/main/db/patients.ts` — read path; no audit row written.
- `src/renderer/src/pages/SettingsUsers.tsx` → `window.api.users.{create,remove,resetPin}` → `src/main/auth/index.ts` (admin-gated) — the admin-only paths.
