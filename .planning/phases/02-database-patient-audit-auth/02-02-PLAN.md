# Phase 2 Plan 02 — Patient CRUD + search IPC + audit integration

## Objective

Ship the patient repository, the `patients:*` IPC surface (list, get, create, update, soft-delete, restore), search by name substring + MRN exact match, pagination, and audit-log integration for every mutation. The schema (`patients` table + indexes) already ships in Plan 02-01's `0001_init.sql` so this plan is purely query + IPC; no new migrations.

**User story (MVP mode):** *As a logged-in doctor, I want to create a patient and find them again by name or MRN so that I can keep track of the people I scope procedures to.*

**Action:**
- Create `src/main/db/patients.ts` exporting `patientRepo`. The repo owns the prepared statements (`insert`, `get`, `getIncludingDeleted`, `list`, `update`, `softDelete`, `restore`) cached in a module-level object so they are compiled once. Row shape matches the `Patient` type in `src/shared/ipc-contract.ts` (`id`, `fullName`, `dob`, `gender`, `mrn`, `phone`, `notes`, `createdAt`, `updatedAt`, `deletedAt`).
- Implement `patientRepo.create(input)`: generates a `randomUUID`, sets `createdAt` and `updatedAt` to `Date.now()`, runs the insert, returns the row. The MRN uniqueness index (`UNIQUE INDEX idx_patients_mrn ... WHERE mrn IS NOT NULL AND deleted_at IS NULL`) handles collision; on `SqliteError` with `code = 'SQLITE_CONSTRAINT_UNIQUE'`, throw `IPC_VALIDATION { field: 'mrn' }`.
- Implement `patientRepo.get(id)` and `patientRepo.getIncludingDeleted(id)` — the read paths default to `deleted_at IS NULL`; the restore flow uses the deleted-aware variant.
- Implement `patientRepo.list({ search, mrn, includeDeleted, page, pageSize })`: builds a parametrized `WHERE` clause with `deleted_at IS NULL` (unless `includeDeleted`); optional exact `mrn = @mrn`; optional substring `full_name LIKE @search COLLATE NOCASE` with `@search = '%' + search + '%'`. `ORDER BY full_name COLLATE NOCASE`. `LIMIT @limit OFFSET @offset`. Default `pageSize = 25`, max `200`; `page` defaults to `1`. Returns `{ rows: Patient[]; total: number }` (the renderer needs `total` for pagination).
- Implement `patientRepo.update(id, patch)`: load current row, merge, write, return row; throws `IPC_NOT_FOUND` if the row is missing or soft-deleted.
- Implement `patientRepo.softDelete(id)` and `patientRepo.restore(id)`: write `deleted_at = ?` / `deleted_at = NULL`; rowcount > 0 is the success signal.
- Create `src/main/ipc/patients.ts` exporting `registerPatientsIpc()`. Registers the IPC channels `patients:list`, `patients:get`, `patients:create`, `patients:update`, `patients:softDelete`, `patients:restore` against `IPC.PATIENTS_*`. Every handler validates its input via `src/shared/validators.ts` (`patientInput` for create + update; `id` regex for get/softDelete/restore).
- Add `createPatient({ input })` to `src/main/auth/index.ts` (or equivalently a thin `patientService.ts` next to `patients.ts` — pick the latter if it keeps the diff focused): wraps `patientRepo.create` in a `db.transaction(...)` that also writes `audit({ action: 'patients.create', entityType: 'patient', entityId: row.id, userId: session.currentUserId })`. The handler returns the row.
- Extend `src/shared/ipc-contract.ts` with `IPC.PATIENTS_LIST`, `IPC.PATIENTS_GET`, `IPC.PATIENTS_CREATE`, `IPC.PATIENTS_UPDATE`, `IPC.PATIENTS_SOFT_DELETE`, `IPC.PATIENTS_RESTORE`. Extend `IpcContract` `patients` namespace with the six methods below (matches RESEARCH.md §IPC Contract Extension):
  - `list(query): Promise<{ rows: Patient[]; total: number }>`
  - `get(id): Promise<Patient | null>` — returns `null` for soft-deleted
  - `create(input: Omit<Patient, 'id' | 'createdAt' | 'updatedAt' | 'deletedAt'>): Promise<Patient>`
  - `update(id, patch): Promise<Patient>` — throws `IPC_NOT_FOUND` if missing
  - `softDelete(id): Promise<{ ok: true }>`
  - `restore(id): Promise<{ ok: true }>` — admin only (session.currentUserId's user must have `isFirstAdmin === 1`)
- Wire `registerPatientsIpc()` into `src/main/index.ts` AFTER `getDb()` and after `registerAuthIpc()` / `registerUsersIpc()` (added in Plan 02-01).
- Extend `src/main/startup-log.ts` so the boot log records `patients-ipc-registered` after the IPC handler registers.

Add `idInput = z.object({ id: z.string().uuid() })` for the singletons.

  - Calls `auth:bootstrap` (sets the admin session via Plan 02-01's helper), then `patients:create` with a full 6-field input; asserts the returned row has `id`, `createdAt`, `updatedAt` populated; asserts an `audit_log` row was written with `action = 'patients.create'`, `entity_type = 'patient'`, `entity_id = <id>`.
  - Calls `patients:create` with a duplicated `mrn` and asserts `IPC_VALIDATION { field: 'mrn' }`.
  - Calls `patients:create` with a missing `fullName` and asserts `IPC_VALIDATION { field: 'fullName' }`.

## Threat Model

| Threat | STRIDE | ASVS | Mitigation |
|--------|--------|------|------------|
| Renderer reading deleted patient directly | Information Disclosure | V4 | `patientRepo.get` filters `deleted_at IS NULL`; Renderer has no other DB access; `getIncludingDeleted` is a main-only utility |
| Hard-delete via UI bypass | Tampering | V4 | No `patients:delete` IPC channel exists; soft-delete is the only path; verified by `git grep` |
| MRN collision via concurrent insert | Tampering | V5 | `UNIQUE INDEX idx_patients_mrn ... WHERE mrn IS NOT NULL AND deleted_at IS NULL` enforces at the DB layer; the IPC handler translates `SQLITE_CONSTRAINT_UNIQUE` to `IPC_VALIDATION { field: 'mrn' }` |
| Audit-row forgery on a patient mutation | Repudiation | V8 | `audit()` insert is in the same `db.transaction(...)` as the patient mutation; a trigger abort rolls back the patient row too |
| Field-level PII in audit metadata | Information Disclosure | V8 | `patientRepo.update` audit `metadata` is `{ fields: string[] }` (the column names, not the values); verified by `tests/main/audit/every-mutation.test.ts` |
| `includeDeleted` flag leaking from renderer | Information Disclosure | V4 | Flag is opt-in (default `false`); renderer must explicitly pass `true`; the IPC handler runs through `src/shared/validators.ts` so the boolean is type-checked |
| Restore as non-admin | Elevation of Privilege | V4 | `restorePatient` checks `session.currentUserId` and `userRepo.get(...)?.isFirstAdmin === 1`; throws `IPC_VALIDATION` otherwise; verified by `tests/main/patients/soft-delete.test.ts` |
| DoS via wild-card search | Denial of Service | V11 | `LIKE '%q%'` is parameterized; `pageSize` is capped at 200; `total` is returned so the renderer can paginate; FTS5 is the v2 upgrade path (SRCH-04) |

## Must-Haves

### Truths
- A logged-in admin can create a patient with all 6 fields (name, DOB, gender, MRN, phone, notes) and the row persists.
- A logged-in user can search patients by name substring (case-insensitive) and by MRN exact match.
- A logged-in user can view, edit, and soft-delete a patient.
- Soft-deleted patients disappear from the default list; the `includeDeleted` toggle reveals them with a `deletedAt` field.
- Patient restore is admin-only; non-admin attempts throw `IPC_VALIDATION`.
- Every `create` / `update` / `softDelete` / `restore` writes an `audit_log` row in the same transaction.

### Prohibitions
- **No hard delete on `patients`** — soft-delete via `deleted_at` only; no `DELETE` IPC.
- **No audit writes on reads** — `list` / `get` are silent; audit log is for mutations.
- **No MRN reuse while a row is active** — unique index excludes soft-deleted rows so re-use is possible after soft-delete.
- **No raw SQL in the renderer** — the renderer never sees `patients` table; all access goes through `patientRepo` + IPC.

### Key Links
- `src/main/auth/index.ts` (or `patientService.ts`) ⊃ `src/main/db/patients.ts` ⊃ `src/main/db/audit.ts` — every mutation is `db.transaction(() => { mutate; audit(...) })` so rollback is atomic.
- `src/main/ipc/patients.ts` → `src/main/auth/index.ts` — the IPC handler is a thin shim; the service function is the only place audit integration happens.
- `src/shared/validators.ts` ↔ `src/main/ipc/patients.ts` — zod schemas re-validate every input defensively.
