# Phase 2 Plan 02 — Patient CRUD + search IPC + audit-on-every-mutation

<objective>
Ship the `patients` repository (`patientRepo.create/get/list/update/softDelete/restore/getIncludingDeleted`), the `patients:*` IPC surface (list, get, create, update, softDelete, restore), name substring + MRN exact search, pagination, and audit-log integration for every mutation AND every read (per ROADMAP Phase 2 success criterion 5 + Fix 6). The `patients` table already ships in Plan 02-01's `0001_init.sql` so this plan is purely query + IPC + audit writes; no new migrations. Plan 02-03 builds the renderer on this IPC.

**As a** logged-in doctor
**I want to** create a patient, find them again by name or MRN, view their details, edit them, and soft-delete the record
**so that** I can keep clinical records organized and the audit log captures every access for compliance.

</objective>
