```ts
ipcMain.handle(IPC.SCREENSHOTS_GET_BLOB, async (_event, input) => {
  const { id } = z.object({ id: z.number().int().positive() }).parse(input);
  const row = screenshotsRepo.getById(id);  // existing
  if (!row) return { ok: false, code: 'IPC_SCREENSHOT_NOT_FOUND' };
  const path = resolveScreenshotPath(row);  // helper to get absolute path
  const bytes = await fs.promises.readFile(path);
  return { ok: true, bytes: new Uint8Array(bytes), mimeType: 'image/jpeg' };
});
```

**Fix 2 — Free-form polygon crop:**

In `src/renderer/src/components/ScreenshotCropModal.tsx`:
- Change state from `selection: {x,y,w,h} | null` → `points: {x:number, y:number}[]` (polygon vertices in image pixel coords)
- Mouse handlers:
  - `onClick` on canvas: if not currently drawing, start a new polygon (set `points = []`)
  - `onClick` again: add a vertex at the click position (snapped to image bounds)
  - `onDoubleClick`: close the polygon (finalize the shape)
  - `Escape` key: cancel current polygon
  - `Backspace` key: remove last vertex
- Render polygon as SVG overlay (`<svg>` with `<polygon>` element) positioned over the canvas
- Render vertex dots for each click
- For preview during drawing, render lines between consecutive vertices
- Apply button: requires `points.length >= 3` (a polygon needs 3+ vertices)
- Pass polygon to crop IPC

Update the crop IPC to accept either polygon or rectangle:
```ts
export interface ScreenshotCropInput {
  id: number;
  croppedBase64: string;  // base64 for contextBridge reliability (per Plan 14 deviation)
  originalDimensions: { width: number; height: number };
  cropPolygon?: { x: number; y: number }[];  // polygon vertices (preferred for free-form)
  cropRect?: { x: number; y: number; width: number; height: number };  // legacy rectangle (backward-compat)
}
```

In `src/main/screenshots/crop.ts`:
- When `cropPolygon` provided: use canvas-like polyfill OR use the bounding box of the polygon
  - For v1 simplicity: compute the bounding box of the polygon, do a rectangle crop of that bbox, then apply the polygon as a mask (transparent outside polygon)
  - The simplest implementation: render the polygon onto an offscreen canvas of the bbox size, set the bitmap to fully opaque inside the polygon, transparent outside; use that as the alpha mask for the cropped image
- When `cropRect` provided: legacy rectangle crop (backward compat with any existing data)

For v1 implementation of the polygon mask: use a Node.js image library. Since we're avoiding new native deps, we can use a simple approach:
- Compute the bounding box of the polygon
- Render the polygon as a path onto a canvas (using node-canvas OR a pure-JS lib)
- Apply the mask: for each pixel in the bbox, check if it's inside the polygon (point-in-polygon test); only include pixels inside

For simplicity, v1 implementation: just use the bounding box. This loses some of the polygon's "free-form" precision but avoids the image-mask complexity. User can iterate to v1.1 with proper polygon masking.

So Fix 2 simplifies to: update the crop UI to take polygon points, compute the bbox on the main side, crop the bbox region, return the result. UI shows the free-form polygon but the actual crop is bbox-based (still much better than no crop).
