<objective>
Fix 2 user-reported issues from Plan 17 UAT iteration:

1. **Crop modal canvas stale after crop** — the modal's <img> doesn't update after a successful crop because the modal fetches its blob URL only on mount. Pass the parent (Lightbox) cacheBuster as a prop and re-fetch when it changes.

2. **"Crop failed" toast on opening the modal** — getBlob is returning ok:false. Surface the actual IPC error code in the error display + add a Retry button so the user can recover without leaving the modal.

Most likely cause of the getBlob failure: the `screenshotId` passed to the modal is the screenshot record's `id` field, which should match the DB primary key. The main-side handler does `screenshotsRepo.get(id)` then reads the file at `<userData>/<screenshot.filePath>`. If `id` is wrong OR the file doesn't exist, getBlob returns `{ok: false, code: 'IPC_SCREENSHOT_NOT_FOUND'}`. The modal needs to surface this code so we can diagnose — but we should ALSO add a fallback path that uses the existing media-server URL (the screenshot is already served via the local HTTP server for the timeline thumbnails, so the URL works for display).

Why this matters: the user can't even open the crop modal successfully right now. The "crop failed" message provides no diagnostic. With the actual code surfaced + Retry button, the user (or a future maintainer) can immediately see what's wrong.

</objective>
