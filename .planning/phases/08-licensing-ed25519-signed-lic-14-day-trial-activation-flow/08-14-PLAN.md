<objective>
Add a Crop action to the screenshot flow. Doctors take screenshots mid-procedure (SCRN-01); sometimes the framing includes extra UI chrome, irrelevant anatomy, or adjacent procedure imagery. A doctor should be able to crop a screenshot to focus on the relevant area without leaving the procedure room or losing the original context.

Scope: when viewing a screenshot at full size (ScreenshotLightbox), the doctor clicks Crop, drags a selection rectangle, clicks Apply. The source JPEG is overwritten with the cropped version. A `screenshot.cropped` audit row records the operation metadata (original + new dimensions + crop rect + byte size).

Why renderer-side crop (vs. main-side image lib): Electron renderer has the Canvas API built-in. Cropping in the renderer = no new native deps (sharp/node-canvas would add ~30MB install), no IPC bandwidth for sending the full image back, and we can use the existing `<img>` + canvas drawImage + toBlob pipeline. The IPC sends just the cropped Blob bytes (typically much smaller than original) + dimensions for audit.

Why permanent crop (vs. non-destructive coords): clinical evidence is the JPEG itself. A doctor cropping a polyp image needs the cropped version to be the actual file on disk — when attached to a PDF report (Phase 6), the PDF renderer reads the source JPEG and would otherwise show the un-cropped version. Permanent crop keeps the report pipeline simple. Audit row provides the "what was cropped" trail.

</objective>

**Step 2 — Main-side handler (src/main/ipc/screenshots.ts + new src/main/screenshots/crop.ts):**

Create `src/main/screenshots/crop.ts`:
- `cropScreenshot({id, croppedBytes, originalDimensions, cropRect}) → ScreenshotCropResult`
- Steps:
  1. Look up the screenshot row by id (via existing `screenshotsRepo.getById(id)` — check repo name in `src/main/db/screenshots-repo.ts`)
  2. Resolve the absolute path: `<userData>/data/media/patients/<p>/<proc>/screenshots/`
  3. Validate `cropRect` is within `originalDimensions` (clamp or reject — pick reject for safety)
  4. `fs.writeFileSync(absolutePath, Buffer.from(croppedBytes))` — overwrites the source
  5. Emit audit row: `audit({ action: 'screenshot.cropped', entityType: 'screenshot', entityId: id, userId: session.currentUserId, metadata: { originalWidth, originalHeight, cropRect: {x,y,w,h}, newWidth: croppedImageData.width, newHeight: croppedImageData.height, byteSize: croppedBytes.byteLength } })`
  6. Invalidate the screenshots cache (if any exists) — check if `screenshotsRepo` has a cache; if not, no-op
  7. Return `{ ok: true, newDimensions: { width: croppedImageData.width, height: croppedImageData.height }, byteSize: croppedBytes.byteLength }`
- Failure cases:
  - Screenshot not found → `{ ok: false, code: 'IPC_SCREENSHOT_NOT_FOUND' }`
  - Invalid crop rect (outside original) → `{ ok: false, code: 'IPC_INVALID_CROP' }`
  - File write error → `{ ok: false, code: string }` with the error message in the audit row
