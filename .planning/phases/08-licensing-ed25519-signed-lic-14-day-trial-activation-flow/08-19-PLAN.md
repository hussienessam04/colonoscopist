<objective>
Fix the "browser rejected blob" error: the screenshot's bytes from getBlob IPC are reaching the renderer but the browser refuses them when loading the `<img>`.

Root cause: main-side returns `new Uint8Array(bytes)` where `bytes` is the Buffer from `fs.promises.readFile`. The Uint8Array view shares the Buffer's underlying ArrayBuffer. When Electron's IPC serializes this for the contextBridge, the renderer receives a value whose underlying ArrayBuffer is not usable as a BlobPart — the browser rejects it.

Fix: send a clean fresh ArrayBuffer (no Buffer view, no shared buffer). Change the IPC contract type from Uint8Array to ArrayBuffer. The renderer wraps it in a Uint8Array for Blob construction. This is the canonical pattern for binary IPC payloads in Electron.

Why this fixes both reported symptoms:
1. "browser rejected blob" — the bytes now survive IPC as a usable BlobPart
2. "canvas didn't update until I leave/re-enter" — when cacheBuster bumps, the re-fetched bytes now load correctly (no error state → image actually displays the new cropped version)

</objective>
