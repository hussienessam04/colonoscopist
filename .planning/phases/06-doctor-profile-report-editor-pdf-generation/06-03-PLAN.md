<risk_model>
- **`@react-pdf/renderer` Image buffer shape**: the lib expects `Buffer | string | URL`. Plan 06-01 Task 8 + Plan 06-03 Task 3 both pass `Buffer` directly — verified by the @react-pdf/renderer docs + the smoke test.
- **`shell.openPath()` on Windows**: returns `Promise<string>` (empty string on success, error message on failure). The handler checks for non-empty string and throws `IPC_INTERNAL`. Risk: a path that the OS can't open (e.g., user deleted the file between render and open) — surface as toast in the renderer.
- **`shell.showItemInFolder()` on Windows**: synchronous; no error return. The handler emits the audit row regardless of success — acceptable per Electron docs.
- **Multi-page screenshot rendering**: each `<Page>` adds overhead; a report with 50 screenshots renders 51 pages. The smoke test attaches only 2 to keep runtime low. A future perf concern is deferred to v1.1.
- **Smoke test cleanup**: the test writes to `<userData>/data/` paths; cleanup MUST be a `fs.rmSync({ force: true })` in a `finally` block so a thrown assertion doesn't leak files. Add a try/finally around the rendering.
- **AR bidi (Pitfall 8) deferred to Phase 7**: the Phase 6 PDF is English-only per D-10. The `RPT-06` requirement is split: EN rendering + EN smoke test (this plan) ships; AR rendering + AR smoke test (Phase 7 i18n) lands later. The Pitfall 8 mitigations (numeric fragment isolation + Latin fragment `direction: 'ltr'`) are not implemented in Phase 6 because they don't apply to English-only output.
- **D-13 one-way decision**: `@react-pdf/renderer@^4` is pinned in `package.json`. Upgrading to v5+ requires manual testing because v5 has React 19-only peer dependency. Defer the upgrade to a separate phase.
