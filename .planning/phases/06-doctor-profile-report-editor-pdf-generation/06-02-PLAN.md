    2. Export `type SaveStatus = 'idle' | 'saving' | 'saved' | 'error'`.
    3. Export `export function useAutoSave<T>(opts: { value: T; onSave: (value: T) => Promise<void>; debounceMs?: number }): { status: SaveStatus; savedAt: number | null; trigger: () => void }`:
       - `debounceMs` defaults to 300.
       - `trigger()` calls the debounced save: sets status to 'saving', awaits `onSave(value)`, on resolve sets status to 'saved' + `savedAt = Date.now()`; on reject sets status to 'error'.
       - `useEffect` cleanup: cancels the debounce on unmount.
       - The hook does NOT fire `trigger()` on every value change — `trigger()` is called explicitly by the parent on blur (or on Finalize for a non-blur trigger). This matches the CONTEXT.md auto-save-on-blur pattern (not auto-save-on-keystroke).
    4. Return `{ status, savedAt, trigger }`.
  </action>

<risk_model>
- **Auto-save IPC storm** is mitigated by the 300ms debounce on blur (not on every keystroke). The hook is explicit: parent must call `trigger()`. Risk: a future parent calls `trigger()` on every change without debounce — defense: add a `useAutoSave` ESLint rule or comment-only safeguard.
- **`useReport` SWR + `setLocal` race**: a concurrent refresh could overwrite the local optimistic update. Mitigation: `setLocal` patches a snapshot; the next `refresh()` fetches the authoritative row (which has the saved patch because the IPC awaited before refresh). Risk: refresh during a slow IPC returns a stale row that overwrites the just-saved patch — defense: gate `refresh()` on the IPC promise (`await onSave(patch)` BEFORE `await refresh()`).
- **ScreenshotTimeline drag-and-drop** uses native HTML5 DnD — accessible, no new dep. Risk: DnD events fire on touch devices differently; defense: defer touch support to v1.1 (desktop-only per the project baseline).
- **`api.profile.uploadSignature` magic-byte sniff** is performed client-side (UX speed) AND at the IPC boundary (Plan 06-01 Task 11). Defense in depth — even if the renderer bypass is buggy, main rejects.
- **Finalize race** between the renderer click and a concurrent edit: the renderer awaits `finalize`; a concurrent `updateDraft` would 0-row-affect (status guard). The renderer surfaces the error as a toast and re-fetches the row.
