<risk_model>
- **D-01 doctor_profile schema migration is irreversible** (table is referenced by RPT PDF generation + audit history). Risk: a future phase wants to add a column — handle via a new `0005_*.sql` migration, NOT by altering `0004`. The migration runner applies migrations in order; later migrations can extend, never alter earlier ones.
- **D-05 1:1 reports-per-procedure UNIQUE constraint** is also irreversible (the procedure FK + UNIQUE shape is referenced by every report IPC). Risk: a clinic needs two reports for one procedure — out of scope, flagged in Deferred Ideas (multi-version report history).
- **`@react-pdf/renderer` in main process** runs as a regular Node module — no sandboxing concerns, but the renderer is still sandboxed (no direct import of `@react-pdf/renderer` from renderer code). The thin Node bridge pattern (renderer passes data over IPC, main calls `pdf(...).toFile(...)`) keeps the security baseline intact.
- **`shell.openPath()` on user-supplied paths** is gated behind `requireSession()` + the path is read from the DB (not directly from renderer input). The renderer never sends a `pdfPath` — only the `reportId`; main looks it up.
- **Profile upload magic-byte sniff** is a defense-in-depth check; the actual disk-write also uses `fs.writeFileSync` to a controlled `userData` subpath. A malicious renderer cannot escape via a path-traversal payload because the path is computed server-side from `userId + 'signature.png'` (no user input in the path).
- **Audit metadata leakage**: `profile.signature_uploaded` audit metadata includes the userData-relative path — safe per Anti-Pattern 2 (no absolute paths in audit logs).
</risk_model>
