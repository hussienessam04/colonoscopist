## Spacing Scale

Declared values (multiples of 4 — matches existing Phase 6 settings-page pattern):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-text gap, badge padding |
| sm | 8px | Compact element spacing (filter row gap, table cell padding) |
| md | 16px | Default element spacing (Card body, form row gap) |
| lg | 24px | Section padding (Card padding, dialog gutter) |
| xl | 32px | Layout gaps (between page header and content) |
| 2xl | 48px | Major section breaks (page-level top padding) |
| 3xl | 64px | Page-level spacing (3xl not used in renderer body — header `p-6` = 24px stays) |

**Exceptions:**
- **Audit row height:** `min-h-[36px]` (9) — compact list per AUDIT-01 "high-volume" requirement + Pitfall §Performance Traps ("per-row re-render of audit log — paginate at 100/page"). 36px keeps 28 rows dense.
- **Filter sidebar width:** `lg:w-72` (288px) — findable on 1366×768, doesn't squeeze Patient List (`minmax(0, 1fr)`).
- **Audit row detail dialog:** `max-w-2xl` (672px) — fits pretty-printed JSON without horiz-scroll.
- **Restore preview dialog:** `max-w-2xl` (672px) — same JSON + size-count UI.

## Typography

Phase 7 does NOT introduce a new type scale. It inherits the scale already established across Phase 2–6 (PatientsList, SettingsHub, SettingsCapture, ProfileEditor).

| Role | Size | Weight | Line Height | Tailwind class | Where it appears |
|------|------|--------|-------------|----------------|------------------|
| Page heading | 24px | 600 | 1.2 | `text-2xl font-semibold` | `Settings → Audit`, `Settings → Backup & Restore` page `<h1>` |
| Section heading | 20px | 600 | 1.2 | `text-xl font-semibold` | Card titles for Audit filters + Backup subsections |
| Body + subheading + mono | 14px | 400 (subheading 600) | 1.5 | `text-sm` (subheading: `font-semibold`; mono: `font-mono`) | Default body — table cells, form labels, dialog description. Subheading bumps weight only (no size bump). Mono adds `font-mono` for audit metadata JSON preview + restore preview zip path |
| Label + timestamp | 12px | 600 | 1.2 | `text-xs font-semibold` (label adds `uppercase tracking-[0.2em] text-muted-foreground`; timestamp adds `tabular-nums`) | Page kicker ("Settings", "Workspace"), Settings sidebar "Sections"; audit row timestamp column (locale-aware `Intl.DateTimeFormat`) |

**Two weights only:** 600 (page heading, section heading, subheading weight-bump, label, timestamp) and 400 (body, mono). No intermediate `font-medium` (500) — audit row timestamps use the same 600 as labels.

**Line-height rule:** body + subheading + mono = 1.5; headings + label + timestamp = 1.2. Matches Phase 6 ProfileEditor `lineHeight: 1.4` for textareas.

**RTL exception:** in `dir="rtl"` mode, the EN-vs-AR font swap happens inside the iframe-rendered PDF (NotoSansArabic) only. The chrome (Card, Button, Dialog) uses `font-sans` system stack — Arabic in the chrome is rendered by the OS Arabic fallback (Segoe UI Arabic on Windows, Geeza Pro / default on macOS, Noto Sans Arabic on Linux). The 14px body weight stays 400 (matches existing SettingsHub / SettingsCapture).

## Color

Tokens are inherited from `src/renderer/src/styles/globals.css` (slate light). **No new CSS variables are added in Phase 7.** The whole product is slate-light; no dark mode is in scope (per existing app — dark mode is rendered by the OS / not in product).

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-slate-50` (background) — `--background: 0 0% 100%` (page) | Page background, SettingsHub shell, the floor under every card |
| Secondary (30%) | `bg-card` (`--card: 0 0% 100%`) + `border` (`--border: 214.3 31.8% 91.4%`) | All Cards, sidebar `<aside>`, dialog content, table rows |
| Accent (10%) | `bg-primary` (`--primary: 222.2 47.4% 11.2%` — slate-900) | Primary CTA button ONLY (Save, Create Backup, Restore, Apply Filters). Active sidebar tab. Active filter chip. |
| Accent secondary | `bg-accent` (`--accent: 210 40% 96.1%`) | Hover state on outline Button + ghost Button + SelectItem focus |
| Destructive | `bg-destructive` (`--destructive: 0 84.2% 60.2%`) | Restore Confirm button (destructive), "Delete audit filter" × button, "Remove media file" — NEVER on a recording Record button (that's already in Phase 4) |
| Muted text | `text-muted-foreground` (`--muted-foreground: 215.4 16.3% 46.9%`) | Field helpers, CardDescription, page kicker, "X total" line |
| Success | N/A — toast.success from `sonner` (green) is the only success color; no custom token |

**Accent reserved for:** active sidebar tab, primary action button (Save / Create Backup / Activate Restore / Apply Filters), the "selected" checkbox & radio chip, the active row in a paginated list (Phase 7 not used), the "favorite" pictograph (Phase 7 not used). **NEVER** for: link text, hover states on neutral elements, decorative borders, captions. A red button is always destructive — never a primary CTA.

**RTL:** accent color is symmetric. No RTL-specific color tokens. The `bg-slate-50` page background and `bg-card` card surface render identically in LTR and RTL.
