## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Renderer → main IPC | backup.pickDestination / create / reveal + restore.pickZip / preview / unpack / revealStaging cross here; zod validates paths |
| Main → filesystem | createBackup writes zip; unpackRestore writes to staging dir; shell.openPath + shell.showItemInFolder invoked |
| Renderer → UI | ConfirmDialog gates Restore to staging; Alert shows warning; Tooltip explains v1.1 placeholder |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-22 | Tampering | Renderer passes arbitrary zipPath / stagingDir to restore IPC | medium | mitigate | zod validates `zipPath` + `stagingDir` as bounded strings (`.min(1).max(2000)`) in `restorePreviewInput` + `restoreUnpackInput` (Plan 07-01). Plan 07-01's `safeEntryPath` filter (T-07-01) is the defense-in-depth at write time. Renderer cannot pass paths to the active `data/` directory because it has no IPC that resolves userData paths to absolute; the staging dir name is renderer-supplied (`data-restore-${timestamp}`) but main resolves it to `<userData>/data-restore-<timestamp>` via `restoreStagingDir(timestamp)`. |
| T-07-23 | Denial of Service | Renderer spawns N concurrent backup operations | low | mitigate | Create Backup button is `disabled` while in-flight; React serializes user input. |
| T-07-24 | Information Disclosure | Backup reveals clinic data via shell.openPath / showItemInFolder | low | accept | Doctor-initiated reveal — explicit user action. The destination dir is rendered in plain text in the toast action; standard OS file manager behavior. |
| T-07-25 | Tampering | v1.1 Activate button accidentally enabled (regression) | low | mitigate | Test 6 asserts the button is `disabled` + the tooltip text matches v1.1 copy. The button has NO onClick handler in v1 — even if disabled were stripped, the click is a no-op. |

**No high-severity risks introduced by this plan.** The high-risk components (path traversal in yauzl, partial DB backup, integrity check) are owned by Plan 07-01's main-side module. The UI plan is the rendering shell.
</threat_model>
