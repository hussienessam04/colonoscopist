<objective>
Extend the trim UX with frame-level visual feedback so the doctor can see exactly what they're cutting. Three additions, one feature area (the trim visual): (1) screenshot position dots on the scrubber, (2) a tick scale below the scrubber when trim mode is active, (3) in-frame + out-frame JPEG previews in the right-rail trim panel sourced via `captureScreenshot(videoRef)` at `inMs` / `outMs`. Purpose: G-05-12 is a major-severity UX gap — the doctor currently has to play + scrub the video to figure out what frame each trim handle corresponds to. Frame previews + a tick scale + screenshot-position dots make the trim decision visually grounded, matching the clinical-utility bar the rest of the Phase 5 surface has set.

        if (video.readyState < 2) return null;

| Renderer -> `<video>` element (in-frame / out-frame capture) | The captureFrameForTrim helper seeks the video to `atMs / 1000`, awaits `seeked` (1-second timeout), then captures via `captureScreenshot`.
