<objective>
Remove the `windowsVerbatimArguments: true` flag from the trim subprocess spawn at `src/main/recorder/trim.ts:137-140`. The flag was incorrectly inherited from a misreading of PITFALLS §10 — it makes Node pass argv as a single space-joined string with no quoting, which truncates the userData path at the first space (e.g. `C:\Users\Hussien Essam\...` becomes `C:\Users\Hussien` at ffmpeg). With the flag removed, Node's default Windows command-line construction properly quotes the path, matching the recording spawn at recorder.ts:290 and the concat spawn at recorder.ts:1045 (both of which work on this user's machine because they already use the default). Update the stale header comment that claimed the flag 'mirrors Phase 4 concat.ts' (it does not) and add a unit-test assertion that locks the contract so the flag cannot regress.

Purpose: G-05-11 is the LAST blocker in the Phase 5 UAT chain — once trim works on this user's machine, UAT steps 6-7 (verify trimmed mp4 plays, restore original) can be re-run end-to-end. The fix is one line of code in production; the diagnostic + test surface is what prevents the bug class from coming back.

      // "Permission denied". The bug is invisible in the unit suite because
      // the spawn is mocked; this test makes the OPTIONS a contract so any
      // future reintroduction of the flag fails at CI.
      it('applyTrim spawns ffmpeg WITHOUT windowsVerbatimArguments: true', async () => {
        const { procedureId } = await bootstrap();
        fakeSpawnSuccess();
        const { applyTrim } = await import('../../../src/main/recorder/trim');
        await applyTrim({ procedureId, inMs: 5_000, outMs: 25_000 });
        expect(spawnMock).toHaveBeenCalledTimes(1);
        const callArgs = spawnMock.mock.calls[0];
        const options = callArgs?.[2] as Record<string, unknown> | undefined;
        expect(options).toBeDefined();
        // The verbatim flag MUST NOT be present (neither `true` nor `false`
        // — its mere presence would override Node's default quoting).
        expect(options).not.toHaveProperty('windowsVerbatimArguments');
      });

      it('applyTrim spawn options match the recording spawn shape (recorder.ts:290)', async () => {
        // Cross-spawn consistency: the trim spawn should look like the
        // recording spawn minus the device-name argv, with the same options
        // object shape. This is a structural guard — if a future refactor
        // re-introduces the verbatim flag OR accidentally adds
        // `shell: true` (which would re-introduce the truncation bug via
        // a different path), this assertion catches both.
        const { procedureId } = await bootstrap();
        fakeSpawnSuccess();
        const { applyTrim } = await import('../../../src/main/recorder/trim');
        await applyTrim({ procedureId, inMs: 5_000, outMs: 25_000 });
        const options = spawnMock.mock.calls[0]?.[2] as Record<string, unknown>;
        // stdio must be present (the trim relies on stderr capture).
        expect(options.stdio).toEqual(['pipe', 'ignore', 'pipe']);
        // shell must NOT be true (would re-introduce argv-splitting bugs).
        expect(options.shell).not.toBe(true);
        // The full input path must be a SINGLE argv element — Node's
        // quoting handles embedding-in-spaces. If `windowsVerbatimArguments`

        expect(inputArg?.startsWith('"')).toBe(false); // NOT pre-quoted by the caller
      });
    });
