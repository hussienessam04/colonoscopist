<objective>
Fix the "FRAME placeholder instead of captured image" gap (G-05-15) by plumbing the `mediaBaseUrl` + `patientId` props that the ScreenshotTimeline wrapper has been silently missing since Plan 05-07. The `thumbnailSrc?: string` prop on `ScreenshotThumbnail.tsx:31` has had zero call sites since it was declared; the `thumbnailSrc && !errored` conditional at line 93 is therefore always false, the `<img>` never mounts, and the placeholder div is what every thumbnail in the timeline shows. Plan 05-11 only fixed the LIGHTBOX URL composition — the timeline was never wired. The fix is a small refactor that also extracts the URL composition into a shared `screenshotUrl` helper to avoid a 3-way copy between the timeline, the lightbox, and the future PDF preview (Phase 6).

Purpose: G-05-15 is a blocker — the doctor captures frames and the metadata renders (HH:MM:SS strip + × button + expand affordance) but the actual clinical image does not. The screenshot feature is half-finished without this fix: the doctor can capture, can delete, can open the lightbox, but the inline thumbnail in the timeline (the surface the doctor uses most to scan their captures) shows a placeholder. The fix is one prop surface + one helper extraction + two prop plumbing changes.

Output: A new `src/renderer/src/lib/screenshot-url.ts` helper. `ScreenshotTimeline.tsx` accepts `mediaBaseUrl: string | null` and `patientId: string` and composes each thumbnail's `thumbnailSrc` via the helper. `ScreenshotLightbox.tsx` is canonicalized onto the same helper (no behaviour change — just dedup). `ScreenshotThumbnail.tsx` gets a `data-testid` on the `<img>` element for the new contract-guard test. `ProcedureReview.tsx` and `ProcedureRoom.tsx` pass the new props (the room page also gains a `useMediaUrl()` call). A new ScreenshotTimeline test asserts the `<img>` src is composed correctly; a new helper test asserts the leaf-extraction + null-safety contract. 2 contract-guard tests + 4 helper tests + 0 production regressions.
</objective>
